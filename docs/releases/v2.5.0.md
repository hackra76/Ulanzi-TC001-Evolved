# Ulanzi TC001 Evolved — Release v2.5.0 📶

## 📶 Self-Healing Wi-Fi AP Fallback & Automatic Background Reconnection

Release **v2.5.0** resolves a critical Wi-Fi recovery issue: previously, if the Wi-Fi network was temporarily lost or unavailable during boot (e.g. router reboot, transient outage, or power cycle), the device fell back into AP setup mode (`NET_STATE_AP_PORTAL`) and remained stranded there indefinitely without ever attempting to reconnect when the network returned. 

With v2.5.0, the firmware introduces a fully autonomous, self-healing network reconnection engine that maintains SoftAP availability while periodically searching for and reconnecting to saved Wi-Fi networks in the background.

---

### ✨ What's New in v2.5.0

#### 1. 📶 Self-Healing Wi-Fi AP Fallback Engine
- **Solved AP Mode Lockout**: Eliminated the permanent AP mode trap where the clock would stay stuck in `NET_STATE_AP_PORTAL` until manually rebooted or re-configured via a browser.
- **Concurrent `WIFI_AP_STA` Mode**: When saved credentials exist, `Network_StartAP()` initializes the Wi-Fi hardware in concurrent `WIFI_AP_STA` mode. The SoftAP (`Ulanzi-Setup-XXXX`) and captive portal web server stay 100% operational for user configuration, while station mode is kept ready to reconnect.
- **Periodic 30-Second Background Retry Loop**: While in AP mode, if saved credentials exist and no clients are actively connected, the device attempts to reconnect to saved Wi-Fi profiles every 30 seconds (`WIFI_AP_RETRY_INTERVAL_MS`).
- **Interactive User Session Guard**: Background reconnection attempts are automatically postponed while any client station is actively connected to the SoftAP (`WiFi.softAPgetStationNum() > 0`), ensuring zero packet loss or channel-hopping interference while a user is entering Wi-Fi credentials in the web portal.
- **Sequential Profile Recovery**: If multiple profiles are configured in NVS, the retry loop systematically cycles through all saved networks until an active signal is re-established.

#### 2. ⚡ Seamless Display & Service Recovery
- **Automatic SoftAP Teardown**: As soon as station connection is re-established (`WiFi.status() == WL_CONNECTED`), the device stops the DNS server, shuts down SoftAP (`WiFi.softAPdisconnect(true)`), returns to pure `WIFI_STA` mode, and transitions state to `NET_STATE_CONNECTED`.
- **Zero-Touch Display Restoration**: Resets `s_skipAP = false` on reconnect, immediately dismissing the AP setup scrolling ticker and restoring the active carousel screens (Clock, Weather, Crypto, Sensors, Airspace) without requiring manual interaction.
- **Immediate Telemetry & MQTT Resumption**: Home Assistant MQTT, real-time POSIX NTP sync, and Open-Meteo weather services automatically resume synchronization upon link restoration.

#### 3. 📱 Companion App Ecosystem Alignment
- Updated documentation and wiki release badges to align with the companion Android app v1.0.5 release ([hackra76/Ulanzi-TC001-Companion](https://github.com/hackra76/Ulanzi-TC001-Companion)).

### 📦 Installation & Upgrade

#### Over-The-Air (OTA) Update (Recommended)
1. Open the clock's Web Configuration Portal (`http://<device-ip>/`).
2. Go to **Panel 05: FIRMWARE OTA**.
3. Click **Check GitHub Releases** and tap **Install v2.5.0 Now**, or upload `firmware.bin` directly.

#### USB Flashing (First-Time / Clean Install)
```powershell
$env:PYTHONIOENCODING="utf8"; pio run -t upload
```
*Or flash `firmware.factory.bin` directly via ESP Web Tools or esptool at offset 0x0000.*
